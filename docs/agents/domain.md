# Domain docs

This project has a single domain context.

Before exploring domain behavior, read root `CONTEXT.md` and the relevant decisions in `docs/adr/`. Use the glossary's defined terms in specifications, tests, and implementation discussions.

If a future `CONTEXT-MAP.md` exists, use it to locate the relevant context instead. If a referenced domain document is absent, continue; create domain records lazily when a term or material decision is resolved.

Keep `CONTEXT.md` a glossary. Record material architectural trade-offs as ADRs. Surface a conflict with an existing ADR before replacing its decision.
