## Acceptance criteria

- [ ] Perform a clean checkout/install/build/start rehearsal using the documented runtime and dependencies; verify one-command local launch after setup and browser-free CLI workflows.
- [ ] Run all automated checks and reconcile every A01–A30 scenario and all mandatory PDF requirements to implementation, test evidence, or an explicitly disclosed limitation. Do not close the parent specification issue as part of this ticket.
- [ ] Complete the README with setup/platform, architecture/process/data flow, independent binary and waveform specifications, commands/operation contracts, overload/interruption behavior, measured results and methods, verification output, trade-offs, limitations, and next work.
- [ ] Record a concise video of actual configuration, live capture/metrics, stop/finalization, range/channel retrieval/export, playback controls, clean verification, and disposable corruption detection.
- [ ] Ensure demo narration, screenshots, metrics, and PASS claims match the checked application; distinguish skipped preview updates, recorded losses, and verification results.
- [ ] Include compact evidence, a usable video artifact/link, and a walkthrough; exclude large recordings, temporary experiments, and credentials from the repository.
- [ ] Verify the GitHub repository and handoff links work for the intended visibility. Document any reviewer access action the owner must take for a private repository; do not send messages or grant unidentified users access.
- [ ] Produce a final submission checklist and known-limitations statement. Local assessment delivery is complete independently of optional public hosting.
